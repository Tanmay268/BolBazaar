# Deployment

Status: configured and smoke-tested locally (production-mode boot, demo seeding, CORS). **Not yet deployed**: Render and Vercel accounts are the owner's.

| Part | Host | Source |
|---|---|---|
| API (FastAPI) | Render, Docker web service | `render.yaml`, `backend/Dockerfile` |
| Web client (rep app + manager dashboard) | Vercel | `web/` (Vite), `web/vercel.json` |
| Android app | Debug APK built from the same `web/` code via Capacitor | `web/android/` |

## 1. API on Render
1. Push the repo to GitHub (make sure `.env` files are not committed; `.gitignore` excludes them).
2. Render → New → Blueprint → select the repo. It reads `render.yaml`.
3. When prompted, enter the secrets: `GNANI_API_KEY`, `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_DEPLOYMENT`, and `CORS_ORIGINS` (your Vercel URL, e.g. `https://bolbazaar.vercel.app`; add `https://localhost,capacitor://localhost` for the Android app).
4. `JWT_SECRET` is generated by Render. `DEMO_MODE=true` seeds the demo users and catalogue on boot even though `APP_ENV=production`.
5. Check `https://<service>.onrender.com/health`; it reports `speech=live,reasoner=live`.

Limits to know:
- The free plan sleeps after inactivity (first request can take ~30–60 s) and its disk is ephemeral. The database is SQLite in `/tmp`, so **data resets on every restart or deploy**; the demo data reseeds automatically. Wake the service before a demo. For durable data use a Render Postgres instance and set `DATABASE_URL=postgresql+psycopg://…` (install with `pip install ".[postgres]"`; Postgres is untested here).
- `GNANI_DAILY_CALL_BUDGET` (300 on Render) is a hard stop that protects credits.
- Keys live only in Render's environment, never in the web bundle.

## 2. Web on Vercel
1. Vercel → Add New Project → import the repo → set **Root Directory** to `web`.
2. Framework preset: Vite (build `npm run build`, output `dist`).
3. Environment variable: `VITE_API_URL=https://<service>.onrender.com` (no trailing slash).
4. Deploy. `vercel.json` rewrites all paths to `index.html`.
5. Microphone capture needs HTTPS, which Vercel provides.

## 3. Android (debug APK)
Prerequisites: Android Studio (for its JDK), Android SDK 36.
```
cd web
echo VITE_API_URL=https://<service>.onrender.com > .env.production
npm run build && npx cap sync android
cd android
# local.properties needs sdk.dir with forward slashes, e.g. sdk.dir=C:/Users/you/AppData/Local/Android/Sdk
JAVA_HOME="<Android Studio>/jbr" ./gradlew assembleDebug
```
The APK is at `web/android/app/build/outputs/apk/debug/app-debug.apk`. The app records 16 kHz WAV exactly like the browser, so audio behaviour is identical. Install with `adb install -r app-debug.apk`.

## Local development
```
cd backend && uv run bolbazaar-api          # http://localhost:8000
cd web && npm install && npm run dev         # http://localhost:5173
```
Copy `.env.example` to `backend/.env` and set `PROVIDER_MODE=live` plus the keys for live speech and extraction; `offline` needs no keys.

## Rollback
Set `PROVIDER_MODE=offline` (or `SPEECH_MODE`/`REASONER_MODE` independently) to fall back to the deterministic providers if a live provider misbehaves during a demo. Offline mode handles only Latin-script Hinglish/English.
